# 众生侧写（npc-parallel） v1.0.0 SillyTavern 扩展

**一句话**：主正文结束后，扩展为「此刻不在场景里」的 NPC 各自补写一段**平行视角**，折叠在 AI 回复下方 —— 主角没看见的那部分世界，照常在发生。

SillyTavern 前端扩展 ｜ 兼容 **1.12+** ｜ 无第三方依赖、无遥测 ｜ 首个正式版

---

## 功能总览
- **双生成通道**：酒馆主API（静默生成，自带完整酒馆上下文）或**自定义API**（OpenAI 兼容独立通道：单独的 URL / Key / 模型 / 温度 / 超时 / **上下文字符预算** / **SSE 流式开关**），一键切换
- **离场检测**：生成前先用一次轻量请求判定名单中谁"在场"，在场者本轮自动跳过（可按 NPC 勾选"免检"）
- **人称可选**：第一人称 / 第三人称有限视角 / 自定义视角宏
- **运行日志**：面板内查看最近 300 条日志（成功耗时、字数、超时、HTTP 报错），支持复制 / 导出 / 清空
- **输出清洗**：自动剥离 `<think>` 推理、代码围栏、`<output>` 等包装标签、Markdown 标题行、开头名牌
- 每名 NPC 独立生成，自动携带其上一回合平行视角的结尾状态，"连续剧式"无缝续写
- 内置"真实角落与隐秘编织"叙事指令：70% 日常生态 + 30% 叙事萌芽、信息隔离与模糊感应、结尾附"知道/不知道/推断/感应"信息岛
- 兼容 SillyTavern **1.12+**

## 安装排障（看不到插件时先看这里）

**① 正确的目录（最常见问题）**

解压后必须保证目录里**直接**是这几个文件，不能多套一层：

```
SillyTavern/data/<你的用户名，默认 default-user>/extensions/npc-parallel/manifest.json
SillyTavern/data/<你的用户名，默认 default-user>/extensions/npc-parallel/index.js
SillyTavern/data/<你的用户名，默认 default-user>/extensions/npc-parallel/style.css
```

❌ 错误示例（多套了一层，酒馆识别不到）：
`.../extensions/npc-parallel/npc-parallel/manifest.json`

❌ 错误位置：放进 `SillyTavern/extensions/`、`SillyTavern/public/extensions/` 都不会被加载。
（老版本酒馆则为 `SillyTavern/public/scripts/extensions/third-party/npc-parallel/`）

**② 放好后必须刷新**：浏览器 `Ctrl + F5` 强制刷新；若仍无效，重启酒馆服务端再刷新。

**③ 判断扩展有没有真的加载**：按 `F12` 打开控制台，刷新后应看到

```
[npc-parallel] 众生侧写 v1.0.0 已加载
[npc-parallel] 悬浮球元素: 已创建 OK
```

- 若**完全没有**这两行日志 → 文件位置不对，或扩展在酒馆「扩展」面板里被禁用（`disabledExtensions`）。请点顶部/侧边的**扩展按钮 → 管理扩展**，确认本扩展是**已启用**状态，然后刷新。
- 若日志里出现 `初始化步骤失败：xxx` → 把该报错发出来即可定位。

**④ 三个入口**（任一可用即可打开设置）
1. 右下角**悬浮球**（🪄）——最可靠，加载成功就一定在
2. 酒馆**「扩展」面板**里的「众生侧写」卡片 → 「打开悬浮设置窗」
3. 输入框左侧**菜单按钮** → 「NPC平行视角 · 设置」

> 注意：设置界面在**悬浮窗**里，扩展面板中看到的是入口卡片而不是完整设置项。

## 一、安装

### 方式 A：扩展面板安装（推荐）
1. 把本目录打包为 zip（或将整个 `npc-parallel` 文件夹推送到任意 Git 仓库）
2. SillyTavern → 顶部 **扩展（Extensions）面板** → **Install extension**
3. 输入 Git 仓库地址；若用 zip，解压到：
   ```
   SillyTavern/data/<你的用户名，默认 default-user>/extensions/npc-parallel/
   ```
   （确保目录内直接是 `manifest.json`、`index.js`、`style.css`）

### 方式 B：手动放置
将 `npc-parallel` 整个文件夹复制到上面的路径，然后刷新页面（或重启 SillyTavern）。

安装成功后，点击右下角**悬浮球**（🪄，可拖拽）呼出悬浮设置窗；也可点左下角**「魔法棒」菜单**（输入框左侧汉堡图标）→ "众生侧写 · 设置" 打开。

## 二、快速开始

1. 打开悬浮设置窗，确认 **启用扩展** 已勾选
2. **生成API** 分组：选"主API"直接跟随酒馆当前连接；要用独立 API 就选"自定义API"，填 Base URL、Key，点「获取模型列表」验证连通（只查 `/models` 端点，**零 token 消耗**，成功后模型名可下拉选择）
3. 在 **NPC 名单** 中点「添加NPC」：
   - **名字**（必填）：与卡里/世界书中该 NPC 的称呼一致
   - **视角**（可选）：该 NPC 专属视角基准；留空用全局人称
   - **备注**（可选）：设定摘要、近期动向，离场扩写时的重要依据
   - **免检**（可选）：跳过在场/离场判定，无论是否在场都生成
4. 发送消息，AI 回复完成 → 自动判定在场/离场 → 为离场 NPC 逐个生成平行视角折叠块
5. 也可手动触发：面板**「通用」**页的 **「立即为最后一条AI回复补写」** 按钮（不必记命令）

## 三、自定义API 说明（独立 OpenAI 兼容通道 · 自带上下文预算）

- **传输方式**：请求**经酒馆服务端代理**（`/api/backends/chat-completions/generate`）转发到你的 OpenAI 兼容端点，浏览器不再直连第三方地址——**彻底没有 CORS、HTTPS 混合内容、内网不可达问题**
- **携带聊天历史**：请求体为标准结构化 `messages` 数组，生成任务会把**主正文之前的全部聊天记录**（自动剥离平行折叠块与 HTML、每条截断 2000 字、同角色合并、总字符预算默认 20000、超出丢最早消息）作为 `user/assistant` 历史消息发送，最后一条 user 消息才是本 NPC 的补写指令——自定义模型因此能读到完整前情，而**不再"只能识别当前正文"**。
  - 「上下文字符预算」设为 `0` 即只发当前提示词（不带历史，最省 token）。
  - 在场判定请求只看当前主正文，**不携带历史**。
  - 主API通道本就走酒馆完整上下文（世界书/角色卡/聊天记录），不受此设置影响。
- **SSE 流式请求（默认开启）**：`stream=true` 经代理透传 `text/event-stream`，边收边拼 `delta.content`，长回复不再容易被网关以 503/超时掐断；端点不支持流式时会明确报错，取消勾选即可回退非流式 JSON。
- **URL 规整**：贴成 `…/v1/chat/completions` 结尾会自动剥掉；裸域名（`https://api.x.com`）自动补 `/v1`；带自定义路径的保持原样
- **自动重试**：429 / 5xx / 网络抖动（含流式网关异常）自动重试最多 2 次（指数退避 + 抖动，尊重上游 Retry-After），偶发限流自愈；4xx 配置类错误立即报出具体原因
- **多端点与失败切换**：备用API 可无限添加。「**轮流使用**」（默认）时，请求按游标依次轮换到各端点 —— 第 1 次用 A、第 2 次用 B、第 3 次回 A…把调用量摊到多个站，各自都不容易撞 RPM；任一端点失败（超时 / 429 / 5xx / 道歉或审核内容）立即顺位尝试下一个，成功即返回并推进游标。选「优先用第一个」则始终从第一个开始，失败才切备用。插件自身**不做限流、不统计调用次数**。
- **轻量任务专用API**：在场判定 / 人物识别这类"不生成正文"的调用可以单独指定一个更便宜的端点（独立分区，**不参与上面的端点池轮换顺序**）；该端点失败时自动回退主池。留空则全部跟随主池。
- **错误可读化**：401/403 → Key 无效；404 → 地址不对（提示补/去 /v1）；400 → 指出是哪个参数不被接口接受并引导用「剔除参数」；识别 `<none>` 占位回复与 `finish_reason=length` 截断
- **响应提取**：优先 `choices[0].message.content`，兼容 `text`、Gemini 风格 `candidates[].content.parts[].text`；识别 `tool_calls` 误返回。**`content` 为空但只有思维链（`reasoning`/`reasoning_content`）时不再把思维链当正文吞下**（那会产出英文推理垃圾），而是明确报错并附上思维链开头，引导关闭推理或调大 Token 上限
- **剔除参数**：某些端点不认 `temperature`/`top_p` 等字段会报 400，把它填进「剔除参数」即可从请求体中删掉（路由必需字段受保护，删不掉）
- **超时**：全生命周期覆盖建连到流式读取结束（默认 180 秒，可调 5s–10min），超时明确报错；主API通道跟随酒馆自身的生成管理
- URL 为空却启用自定义通道时，自动回退主API并在日志中告警

## 四、离场检测（在场则跳过）

- 开启后，每轮先用一次小请求（max_tokens ≤ 400）让模型按主正文判定名单中每个 NPC 是否"亲身在场景中"——只被谈论、被回忆但人不在场的也算**离场**（会生成）；无法确定一律判离场
- 判定为"在场"的 NPC 本轮跳过，toastr 与日志都会注明
- 判定解析失败（识别数不足一半）或请求出错时，按"全员离场"继续生成，不会卡住流程
- 某 NPC 想无视判定（例如主角随身同伴）：在其行内勾选**免检**

## 六、模板占位符

`${xxx}` 与 `{{xxx}}` 写法等价；未被本扩展占用的酒馆宏（`{{user}}`、`{{char}}` 等）会照常替换。

| 占位符 | 内容 |
|---|---|
| `npc_name` | NPC 名字 |
| `npc_pov` | 该 NPC 视角（留空则等于全局人称） |
| `npc_notes` | 该 NPC 备注栏 |
| `evolution_pov` | 全局人称/视角宏 |
| `main_text` | 本回合主正文（纯文本，已剥离旧平行块） |
| `prev_npc_text` | 该 NPC 上一回合平行视角的结尾状态（首回合有提示语） |
| `min_words` / `max_words` | 字数区间 |

**输出解析与清洗**：模型被要求按 `<npc正文>…</npc正文>` + `<npc信息>…</npc信息>` 输出。解析层会自动剥离：`<think>`/`<reasoning>` 推理标签、代码围栏（``` 包裹）、`<output>/<answer>/<reply>/<result>` 等包装标签、开头的 Markdown 小标题与"平行视角"标题行、开头的角色名牌（`名字：`）、零宽字符与 `---`/`***` 分隔线；无标签时会兜底识别`【信息状态】`段落。清洗失败的极端输出原样保留，可在日志中查看原始响应长度。

## 七、各功能在面板的哪里

所有功能都在悬浮窗里（右下角悬浮球 🪄 / 扩展面板入口 / 输入框左侧菜单），没有需要记的命令：

| 想做什么 | 在哪儿 |
|---|---|
| 为最后一条 AI 回复补写全部 NPC | 「通用」页 → 「立即为最后一条AI回复补写」|
| 中途停止本轮补写 | 同一个按钮，生成中会变成「停止补写」（已完成部分保留）|
| 只重做本轮失败的那几个 | 「通用」页 → 「重试失败的 N 个」|
| 清除本条回复上的全部折叠块 | 「通用」页 → 「清除本条」|
| 添加 / 删除 NPC、清空名单、存/套用模板 | 「NPC名单」页 |
| 查看 / 修改 / 重新生成 / 删除某一段平行视角 | 「平行视角」页（按楼层分组）|
| 场景里就跳过、只写不在场的人 | 「通用」页 → 「启用在场/离场判定」|
| 连世界书一起喂给自定义API | 「世界书」页（多选 + 条目级开关 + 试算命中 + 预览注入）|
| 试连通道、看模型列表 | 「API」页 → 「连接并获取模型」（只查 `/models`，零 token 消耗）|
| 查日志 / 复制 / 导出 | 「日志」页 |

重新生成/重掷（含 swipe）时，会先清除旧折叠块再重写，不会叠加。

## 八、与其他变量 / 记忆体系的联动

- **正文随消息进入后续上下文**：折叠块存储在消息文本内，之后每一轮生成，模型都能看到这些平行视角，各类角色变量 / 记忆类扩展脚本按常规处理 AI 消息文本即可读到（即使剥离 HTML 标签，标签内文字仍保留）
- **结构化数据**：每条消息同时写入 `message.extra.npc_parallel`：
  ```json
  [{ "name": "王铁柱", "pov": "", "text": "正文…", "info": "知道：…", "ts": 1695… }]
  ```
- **事件**：补写完成后触发 `MESSAGE_EDITED`，监听该事件的框架会重新处理该消息
- **连续性**：生成时自动向前检索该 NPC 上一次平行视角正文注入模板，保证"紧接上文续写"

## 九、日志与排障

面板底部「运行日志」实时记录（存于浏览器 localStorage，最多 300 条，刷新不丢）：

- 每次生成：成功（耗时/字数）或失败（超时、HTTP 状态码、响应片段）
- 在场判定结果、API 通道切换/回退、模板与连接测试
- 排障顺序建议：先看 `HTTP xxx`（地址/Key/模型问题）→ `请求超时`（调大超时、开启流式或换通道）→ `只输出了思维链/没有正文`（关闭该模型的推理/思维链，或调大「回复Token上限」）→ `端点未按流式返回`（取消「流式请求」）→ 正文格式异常（模型未按标签输出，解析层会兜底，必要时换更强的模型）
- **自定义模型"不知道前文/只认识当前正文"**：检查「上下文字符预算」是否为 0（0=不带历史）；日志中成功记录会标注 `N条历史`，N=0 即未发送历史。注意历史只包含主正文之前的消息，当轮主正文始终通过模板内 `${main_text}` 发送。

## 十、注意事项

- 自动补写基于 `MESSAGE_RECEIVED`（回复完成后触发），流式输出下在流结束后执行；防抖 1.5s 合并排队消息
- 补写期间你发起新的生成，本轮补写自动中断（已完成部分保留）
- 每轮额外消耗：1 次在场判定（不带历史，≤400 tokens）+ N 次（离场NPC数）生成；自定义通道下生成请求含全部上下文（受字符预算限制，想省钱就把预算调小或设 0）
- 群聊同样适用：为最后一条 AI 回复补写
- 卸载：删除 `extensions/npc-parallel` 目录即可；已生成的折叠块属聊天记录，可在悬浮窗「平行视角」页逐条删除，或手动删除消息中 `<!--npcp:start-->` 到 `<!--npcp:end-->` 之间的内容
